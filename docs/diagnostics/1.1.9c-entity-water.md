# Diagnóstico 1.1.9c — entidade visual mínima para schema 1.26.40

## Causa confirmada

O Content Log da 1.1.9b mostrou a cadeia completa:

```text
minecraft:pushable ausente no Schema
→ actor JSON falha ao carregar
→ aspergillum:aspersorium_water_visual não é registrado
→ Dimension.spawnEntity recebe um tipo inválido
→ nenhuma água é renderizada
```

Desde o formato 1.26.10, o componente legado `minecraft:pushable` foi dividido em `minecraft:pushable_by_block` e `minecraft:pushable_by_entity` e deixou de ser analisado. Como a entidade usa `format_version: 1.26.40`, a definição A/B era inválida. A conclusão anterior centrada em `is_summonable` foi prematura: a B preservou o erro porque o JSON nunca chegava ao registro.

## Implementação C

A entidade continua `is_summonable: true` para criação pelo script e `is_spawnable: false` para não expor spawn egg. O legado foi removido e não foi substituído pelos novos componentes, pois ambos são capacidades opt-in de empurrão e a projeção deve ser imóvel.

O Behavior Entity foi reduzido a:

- `minecraft:persistent`;
- `minecraft:cannot_be_attacked`;
- `minecraft:physics` com gravidade e colisão desabilitadas;
- `minecraft:collision_box` com largura e altura zero.

Respiração, imunidade a fogo, família de tipo e otimização de banda foram removidas por não serem necessárias para geometria, material, propriedade sincronizada ou lifecycle. O empacotador exige essa allowlist exata e rejeita explicitamente o componente legado.

## Primeiro gate

Antes de avaliar translucidez, confirmar que o log não contém `actor_definitions`, `failed to load from JSON`, `not present in the Schema` nem `not a valid entity type`. Uma caldeirinha com água deve ganhar sua superfície imediatamente após mudança de state ou em até 80–120 ticks quando já existia no mundo.
