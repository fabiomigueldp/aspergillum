# Release 1.2.4 — Engine-rendered 3D inventory models

**Technical release promotion on 2026-08-11.** Version 1.2.4 replaces the sixteen raster aspergillum inventory icons with engine-rendered 3D visuals derived directly from the authored item mesh, UV layout, and PBR texture families. The production package uses stable Bedrock components and does not require Beta APIs, Upcoming Creator Features, or preview formats.

## Why an internal block bridge is required

Stable custom item definitions expose `minecraft:icon` for inventory UI and do not expose an arbitrary item-geometry component. Attachables can replace the held or equipped presentation, but Minecraft still uses the icon in inventory and on the ground. Bedrock does, however, allow an item without `minecraft:icon` to render the block referenced by `minecraft:block_placer`; the referenced block can independently define its item geometry and materials through `minecraft:item_visual`.

Version 1.2.4 therefore introduces one internal block identifier, `aspergillum:inventory_visual`, with one internal state, `aspergillum:inventory_cosmetic`, whose published values are the existing cosmetic indices `0..15`. Each of the sixteen existing item identifiers points to the corresponding state. `replace_block_item` is deliberately absent, so no item identity is replaced and persistent ItemStacks keep their original type IDs.

## Direct model and material reuse

`tools/generate-assets.mjs` derives `geometry.aspergillum.inventory` from the generated held geometry. It copies every one of the fourteen visual cubes from `handle` and `sprinkler_head` and preserves every per-face UV mapping. The only inventory-specific operations are deterministic framing: centering, uniform normalization to a fourteen-unit height, and a `-35°` presentation tilt.

The inventory geometry does not copy `aspergillum_bound`, `q.item_slot_to_bone_name(context.item_slot)`, presentation/action animation bones, or locators. The approved attachable geometry remains byte-semantically governed by its original `1.16.0` hierarchy and binding. Each item visual selects the same `textures/entity/aspergillum*` color map and the same normal/MER texture set already used by its attachable; no substitute palette or painted icon is involved.

The sixteen 32×32 PNGs and their item-atlas aliases are no longer distributed. Their 1.2.2 authoritative sources and manifest remain under `assets-src/inventory-icons/` solely as reproducible historical evidence.

## Placement safety

`minecraft:block_placer` necessarily carries native placement semantics, so the bridge is protected in depth:

1. every item allows native placement only when used on `minecraft:air`, which is not a normal clicked support block;
2. the proxy block's placement filter requires an air support and an upward face, preventing ordinary supported placement;
3. the proxy has no collision or selection box and is hidden from catalogs and commands;
4. `aspergillum:inventory_visual_guard` cancels `beforeOnPlayerPlace` if native placement is nevertheless attempted;
5. the proxy has no loot component and never participates in charge, water, docking, customization, or persistence logic.

The existing `ItemCustomComponent.onUse` and `onUseOn` routes remain responsible for inspection, loading, docking, and the Sacristan Table. In-game input testing is still mandatory because offline validation cannot prove the ordering of native and custom interaction paths on every control scheme.

## Compatibility guarantees

This release preserves the Behavior Pack and Resource Pack UUIDs, module UUIDs, all sixteen published aspergillum item identifiers, the attachable identifiers, public aspersorium/table/entity identifiers, all pre-existing block states and values, cosmetic indices `0..15`, the held geometry identifier and `1.16.0` format, `aspergillum_bound`, the exact slot binding, first- and third-person poses, animations, VFX trajectories, audio payloads, finite charges, water encoding, sessions, locks, docked snapshots, and persistence.

The only added world-facing definitions are the internal proxy ID and its sixteen-value visual state. They are never intentionally placed or persisted. No migration is required for existing worlds or ItemStacks.

1. Close Minecraft, remove or disable older competing packs, and import only `Aspergillum-1.2.4.mcaddon`.
2. Confirm `[1,2,4]` in both manifests and verify the artifact SHA-256 above.
3. Compare all sixteen finishes in Creative inventory, hotbar, a chest, and the Sacristan Table on light and dark UI backgrounds.
4. Confirm that the complete silhouette, perforated head, handle, pommel, scale, and tilt are readable without clipping; repeat with conventional graphics and Vibrant Visuals.

7. Export a clean Content Log and record platform, controls, graphics mode, screenshots, and observed cache behavior.

## Reproduction

```powershell
npm run package
Get-FileHash -Algorithm SHA256 dist/releases/Aspergillum-1.2.4.mcaddon
npm run addon -- install 1.2.4 --dry-run
```

Offline automation proves package structure, deterministic assets, identity preservation, and placement guards. Only the imported Bedrock client can prove final GUI framing, lighting, cache behavior, and input-route compatibility.
