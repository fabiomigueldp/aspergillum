# Release 1.2.2 — Material and inventory polish

## Decision

**Technical GO and release promotion on 2026-08-11.** Version 1.2.2 combines two presentation-only improvements: material-specific block destruction particles and model-derived inventory icons for all sixteen published aspergillum finishes. The automated production gate and final artifact evidence are recorded below. In-game rendering, cache behavior, Content Log review, and the persistent-world smoke test remain explicit manual gates rather than inferred results.

## Delivered scope

### Material-specific destruction particles

- The aspersorium uses an opaque native `16 × 16` hammered and patinated metal tile with six reviewed colors, `56` particles, and `tint_method: "none"`.
- The Sacristan Table uses an opaque native `16 × 16` tile containing exactly `240` wood pixels, `12` velvet pixels, and `4` brass pixels, with `80` particles and `tint_method: "none"`.
- Both blocks use the stable `minecraft:destruction_particles` component and dedicated `terrain_texture.json` aliases.
- Water and the docked aspergillum are deliberately absent from the destruction tiles, preventing the client from sampling incoherent fragments from the full variant atlases.

### Model-derived inventory icons

- All sixteen `32 × 32` item icons are rendered from the existing aspergillum geometry, color maps, normal maps, and MERS maps instead of being independently illustrated procedural sprites.
- The renderer uses a fixed oblique camera, dedicated inventory lighting, transparent background, presentation-only two-dimensional rotation, premultiplied-alpha resampling, and a minimal one-pixel outline.
- `assets-src/inventory-icons/` stores the promoted native PNGs and a manifest containing renderer version, camera, finish metadata, byte counts, and SHA-256 hashes.
- `npm run render:inventory-icons` produces a review candidate by default. The explicit `--apply` switch promotes approved sources and copies byte-identical outputs into the Resource Pack.
- Normal asset generation republishes the approved sources and cannot silently restore the former procedural drawings.

## Compatibility guarantees

This release does not change pack UUIDs, namespace, public item/block/entity identifiers, cosmetic indices `0..15`, block-state names or values, geometry identifiers, the `1.16.0` geometry format, `aspergillum_bound`, `q.item_slot_to_bone_name(context.item_slot)`, first- or third-person poses, animations, VFX trajectories, audio, charges, water encoding, sessions, locks, snapshots, or persistence. The server remains authoritative for state and gameplay; every 1.2.2 change is client presentation or production tooling.

The official pack cover is carried forward byte-for-byte from 1.2.1. Its manifest retains 1.2.1 as the true render source and records 1.2.2 separately as the current publication, avoiding a false claim that unchanged artwork was rerendered.

## Required in-game QA

1. Remove older installed packs and clear cached copies before importing only `Aspergillum-1.2.2.mcaddon`.
2. Confirm `[1,2,2]` in both imported manifests and match the artifact SHA-256 above.
3. Strike and break empty, full, and occupied aspersoria in Survival and Creative using both classic graphics and Vibrant Visuals. Fragments must remain metallic and must not contain water, leather, gold, or docked-item colors.
4. Strike and break empty and occupied Sacristan Tables. Fragments must read primarily as dark wood with sparse velvet and brass accents.
5. Compare all sixteen icons at native inventory scale in Creative inventory, hotbar, containers, and the Sacristan Table flow, on both light and dark UI contexts.
6. Confirm that inventory, first person, third person, docked composition, and table presentation resolve the same selected finish.
7. Run the normal fill/load/four-sprinkle/dock/undock/table/break/reload smoke test and export a clean Content Log.

## Reproduction

```powershell
npm run package
Get-FileHash -Algorithm SHA256 dist/releases/Aspergillum-1.2.2.mcaddon
```

The package command regenerates approved sources, rebuilds audio and the stable Script API bundle, runs the structural validators, creates the deterministic `.mcaddon`, and validates it with Minecraft Creator Tools. External Three.js captures establish asset provenance and reproducibility but do not replace the final Bedrock client rendering gate.
