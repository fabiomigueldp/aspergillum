# Release 1.2.5 — Runtime-compatible 3D inventory bridge

**Corrective release on 2026-08-11.** Version 1.2.5 fixes the Bedrock 26.40 parser failures introduced by the stateful inventory proxy in 1.2.4 while preserving engine-rendered 3D aspergillum inventory visuals.

## Root cause

The 1.2.4 offline pipeline accepted two constructs that the real client rejected:

1. `minecraft:block_placer.block` was emitted as a block descriptor object containing a name and custom state. Bedrock 26.40 attempted to parse this field as a block identifier string and reported `block: invalid string` for all sixteen items.
2. `minecraft:item_visual` was placed inside the proxy block's cosmetic permutations. The block parser allows this component in the base `components` object but rejected it inside `permutations`.

Once each item JSON failed, the entire item component set was absent from the registry. The warnings about an unused item custom component, missing icons, and the errors about setting dynamic properties on stackable items were downstream effects: `minecraft:max_stack_size: 1` and `aspergillum:aspergillum_use` had never registered. No persistent-state algorithm failed independently.

The current Microsoft Learn reference describes `block` generically, but its only official sample uses a plain string. The `minecraft:item_visual` reference likewise demonstrates base-component declarations. For this runtime target, observed client behavior is the decisive compatibility constraint.

## Corrected structure

- Every item now uses a plain string in `minecraft:block_placer.block`.
- Sixteen hidden internal proxy blocks replace the single sixteen-state block.
- Every proxy is state-free and permutation-free.
- Geometry, `minecraft:material_instances`, and `minecraft:item_visual` are declared together in base `components`.
- All proxies share `geometry.aspergillum.inventory` and select only their corresponding real entity/PBR texture family.
- The raster item icons remain absent from the distributed Resource Pack.

The additional proxy identifiers are internal presentation adapters. All sixteen persistent aspergillum item IDs remain unchanged, so existing ItemStacks and docked snapshots require no migration.

## Placement and state safety

Every proxy retains `use_on: ["minecraft:air"]`, an impossible normal-support placement filter, null collision and selection boxes, catalog/command hiding, no loot, and the script-side `beforeOnPlayerPlace` cancellation guard. The inventory adapters do not read or write charges, water, customization sessions, locks, or snapshots.

## Validation changes

The 1.2.5 validators now fail if:

- any `block_placer.block` is not a string;
- any inventory proxy declares a state or permutation;
- `minecraft:item_visual` is absent from base components or appears through the rejected stateful design;
- an item loses `max_stack_size: 1`, its custom component, ID, or placement restrictions;
- any proxy loses its exact material, geometry, or placement guards.

## Required runtime verification

1. Remove 1.2.4 and cached competing copies, then import only 1.2.5.
2. Confirm that the Content Log contains none of: `item_visual is not allowed`, `block: invalid string`, `Missing icon`, unused aspergillum components, or dynamic properties on stackable items.
3. Inspect all sixteen inventory models and verify that each finish selects the correct metal and grip.
4. Exercise initialization, the Sacristan Table, snapshot recovery, loading, four sprays, docking, undocking, breaking, and reload.
5. Use every item against air, floors, walls, the Aspersorium, and the table; no internal proxy may be placed or consume the item.

## Reproduction


Offline validation proves the corrected JSON shape. Only the Bedrock client can close the runtime parser, GUI rendering, and input-routing gates.
